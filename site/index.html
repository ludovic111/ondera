The DAW you and your agent play together.

Ondera is a cross-platform digital audio workstation with a Logic-like workflow and a hardware-like feel. Every action is a typed command, so an AI agent can edit your session from the terminal while you keep working in the GUI. Same session, same undo history.

    Command layer

    One command layer. Three clients. None of them privileged.

    Every user action in Ondera becomes a named command with typed params. The desktop app dispatches them. So does the command-line tool. So does the MCP server an agent talks to. Anything the GUI can do, an agent can do with the same command, and every change is revertable from the UI.

    GUI

    Click it

    BGVAudio

    The button does not touch the session. It dispatches track.setMute and reads the result back through a subscription, like everything else in the app.

    CLI

    Type it

    $ ondera track.setMute --track bgv --muted false
ok  session 3f9c · undo #12

    The CLI is generated from the command registry, not hand-written. New command in core, new subcommand in the shell.

    MCP

    Ask for it

    {
  "tool": "ondera.dispatch",
  "command": "track.setMute",
  "params": { "trackId": "bgv", "muted": false }
}

    An agent gets the same registry as an MCP server, with the same param schemas, so it never has to guess what a session can do.

    All three panels are wired to the same store as the window above. Mute BGV in any of them and watch the others follow.

    Material system

    Feels like hardware, because it is drawn like hardware.

    One light source, directly above. Every raised object gets the same four layers in the same order: a specular highlight on its top edge, a face that darkens downward, a contact line along the bottom, and a soft drop shadow. Pressed states swap the drop shadow for an inner one and darken the face. Nothing else moves. Try the rack.

    Architecture

    API first. The GUI is just one client.

    Most DAWs are built GUI-first and bolt scripting on afterwards. Ondera's session model and every operation on it live in a pure TypeScript package that has never heard of a screen. That is what makes it safe for an agent to edit a project while you watch.

    Electron UIReact + canvas
    CLIgenerated from the registry
    MCP servergenerated from the registry
    @ondera/core command registry · session store · model · undo · dispatch(command) pure TypeScript · no DOM · no Electron · no Node
    EngineClient · IPC
    Audio engine a separate native process in Rust Phase 1 ships a mock engine behind the same interface
    • No component mutates state. The renderer reads through subscriptions and writes only through dispatch. Hover and drag live in React; anything worth undoing is a command.
    • Commands are deterministic. Same state, same params, same result. No clock and no randomness inside a command; they arrive as params.
    • One tokens file. Every colour, size, gradient and shadow, in canvas and CSS alike. A lint step fails the build if anything else hardcodes one. This page reads the same file.
