# Ondera 0.8.0 (draft, not released)

## Recording
- Input monitoring: hear the microphone through the track's inserts, sends and fader. The button
  beside Arm cycles Off, Auto (while armed, until the track plays its own clip, and again while
  recording) and On; also in the mixer, the inspector, the Track menu and on `I`.
- The built-in microphone into the built-in speakers would howl, so that pairing stays muted
  until you choose Monitor Anyway. Headphones are not affected.
- Settings > Audio > Buffer Frames sets the device buffer (64 to 2048). `audio.status` reports the
  measured input and output buffers, the frames waiting between them and the resulting latency.
- The status line shows "Count-in…" during the count and lets go of a finished MIDI take.

## Files
- FLAC export, 16 and 24-bit, for mixes and stems. It streams: a twenty-minute song grows the
  heap by about 2 MiB. Stems take the chosen file type instead of always being WAV.
- No MP3. There is no mature pure-Rust MP3 encoder: `shine-rs` is LGPL-2.0, months old and has no
  psychoacoustic model; `oxideav-mp3` is MIT but new and unproven; `mp3lame-encoder` is good but
  links LGPL C code into the app and needs a C toolchain on three platforms. If a small lossy
  format is wanted, Ogg Vorbis through `vorbis_rs` (BSD-3-Clause, C libraries) is the clean choice
  by licence; there is no pure-Rust Opus encoder either. Nothing was added without a decision.

## Plugins
- Native plugin ABI 2: controllers, pitch bend and pressure, parameter changes on their sample,
  state of the plugin's own, a tail length and latency-change notices. ABI 1 plugins keep loading
  and new plugins still load in older Ondera versions. The `Plugin` trait is source-compatible;
  a plugin written against `process` gets sample-accurate parameters without changes.
- One browser row per plugin instead of one per channel layout ("(m)", "(s)", "(m->s)", and the
  VST3 "Mono" / "Stereo"); the row loads the layout a stereo track wants.
- Far fewer plugins in Other Effects (353 to 12 on a library of about 2,250).

## CLI, MCP and agent
- 160 commands. New: `track.setMonitor`, `audio.allowSpeakerMonitoring`, `view.fit`, `clip.copy`,
  `clip.cut`, `clip.paste`, `agent.models`, `agent.connection`, `rhythm.preview`, `app.openGuide`.
  `view.get` / `view.set` cover the browser tab and selection, the piano roll's vertical scroll
  and the lane width; `ui.showPanel` covers the command palette; `plugin.list` has `everyLayout`.
- The clipboard is shared: copy in the window, paste from the CLI, or the other way round.
- `session.batch` is one entry in the agent's Changes, as it is one undo step.

## Known limits
- Monitoring closes and reopens the input when a take starts, so there is a short gap in what
  you hear at the start of the count-in. One shared input stream would remove it.
- Two interfaces on different clocks drift: expect an occasional tick (counted in `audio.status`).
- Controllers, pitch bend and pressure reach ABI 2 plugins through the ABI and the test bench;
  the sequencer, the piano roll and the MIDI input do not route them yet.
- Opening the command palette from the CLI could not be confirmed by screenshot, because a
  window in the background pauses its animations; it is covered by a store test.
