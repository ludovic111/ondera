# Ondera 0.6.0

## Three themes, each in dark and light

Settings > Interface now shows three themes as live miniatures, with a Dark / Light / Auto
switch beside them (Auto follows the system while the window is open):

- **Modern.** Flat and quiet. Depth comes from a five-step lightness ladder and one-pixel lines;
  one cool neutral, one accent; only things that float above the window cast a shadow.
- **Skeuomorphic.** The milled hardware of the design sheet. Dark is the graphite unit, value for
  value; light is the same unit in champagne aluminium, with displays and meters kept as smoked
  glass the way real gear does it. The material recipes are re-lit, not redrawn: on a pale face
  highlights start high and rise slowly, and shade uses well under half the dark-theme alpha.
- **Frutiger Aero.** Glass, water and sky. Every raised control is a lens with a bright upper
  reflection, a hard waist and a luminous lower rim; the frame is daylight by day and an aurora
  by night, while lanes, lists and the conversation stay opaque so content never competes with
  the chrome.

The two earlier appearances were produced by rewriting colour strings at run time. They are
replaced by a theme layer (`frontend/src/theme`): a theme is a function of the mode that returns
every colour, gradient, shadow, line, radius and canvas shadow, and the canvases read the live
groups at paint time. Each theme is computed from one neutral ramp in OKLCH plus one accent, and
tests check, for all six variants, that text holds 7:1 on every reading surface (4.5:1 for
secondary text, 3.6:1 for caps labels), that the accent and its label stay legible, that clip
names read on the lightest and darkest track colours, and that the surface ladder keeps its order.

`interface.appearance` is now `modern`, `skeuo` or `aero`, and `interface.mode` is `dark`, `light`
or `auto`. Older settings files are migrated on load: `graphite` becomes Skeuomorphic dark, and
`aero` without a mode stays the light glass it was.

## Stock plugin front panels

The 24 stock plugins no longer open as a list of sliders. Each has a front panel: a nameplate
with its category and presets, a display, one dial per continuous parameter with a value ring
(filling from the centre when the range straddles zero, logarithmic where the plugin says so)
and a selector or switch per choice. Hover a dial for its automation button; double-click resets,
Shift drags finely.

The display draws what the plugin is doing, from the same maths as the audio: the Channel EQ uses
the engine's RBJ shelves and peak, the Filter the state-variable filter's damping, the compressor,
gate and limiter their transfer curves, the saturators their waveshaper, the bitcrusher a crushed
sine, the modulators their LFO (with the stereo offset), Echo its taps, Space its decay, Width and
Utility the stereo field, Transient the reshaped hit, and the instruments their envelope. External
plugins keep the parameter list and their own window.

## Site

The site wears the app's tokens, generated from the same theme layer, so it offers the same three
themes in dark and light: a switcher in the navigation, a Themes section whose cards each render
in their own theme, and an interactive preview and hardware rack that follow the choice. The
captures of the real window were retaken, and the server now gzips text.

## Fixes

- Caps labels on raised menus fell under 3.6:1 in the graphite theme; the label ink is a few steps
  lighter.
- A flat theme has no canvas shadow layers, and the playhead and position bubble were painted only
  once per layer; they are painted once when there are none.
- Buttons inside dialogs overrode the material of toggles and segmented controls.
- Dialog borders, the command palette, mixer strips and a few inspector details used fixed colours.

## Development

`npm --prefix frontend run dev` now works in a plain browser: without the Tauri bridge a
development-only host serves a fixed song, so layouts and themes can be checked with
`?theme=modern|skeuo|aero&mode=dark|light&panel=mixer|settings|plugin:<name>`. It is not part of
production builds.

## Validation and limits

Local macOS validation: frontend type check and 91 frontend tests (theme contrast and round trip,
plugin display maths), `cargo fmt`, Clippy with warnings denied, the workspace tests, and a debug
build driven through the CLI: all six variants, the mixer, the Settings theme picker and a stock
plugin panel were captured from the real window with `ui.screenshot` after switching through
`settings.set`. Windows and Linux were not checked by hand; Frutiger Aero falls back from Segoe UI
to Lucida Grande, Trebuchet MS and Manrope depending on the platform.

Still not built: clip fades and gain, time stretching, comping, tempo changes inside a song and
user-defined buses. The egui reference interface in `desktop/` does not follow the themes. Packages
remain ad-hoc signed without notarization; Windows binaries remain unsigned.
